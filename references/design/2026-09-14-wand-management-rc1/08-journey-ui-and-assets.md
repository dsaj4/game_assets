## UX01 平台、玩家与本版交付边界

首版为Windows桌面、简体中文、单人离线游玩版本，以可独立启动的桌面下载包交付。完整内容范围仍是S2／E3、战前、路线、休整、商店与单阶段首领，不缩减成仅一场演示。

| 项目 | 首版范围 | 边界 |
| --- | --- | --- |
| 玩家情境 | 喜欢卡牌构筑与安排自动执行顺序，愿意战前读牌、战后看原因的玩家 | 不要求编程经验；首次游玩通过可跳过引导理解基础语义 |
| 输入 | 鼠标＋键盘；全部必需动作也有键盘选择路径 | 拖动提供快捷操作；必须同时提供点击选取／放置或方向按钮 |
| 显示 | 横向布局；以1280×720到1920×1080窗口作首轮可读性验收范围，窗口与全屏可切换 | 更宽画面扩展留白，不增加视野或施法范围；小于下限提示调整窗口，不裁掉关键操作 |
| 本地游玩 | 无联网开局门槛、无账号或联机玩法；一份进行中对局 | 不将存档槽数量解释为角色数；独立设置不随新局清空 |
| 发行 | 独立桌面下载包 | 具体商店、售价、付费政策、安装及设备性能规格属于后续发行／制作任务，明确后置，不替它们作商业承诺 |
| 其他平台 | 本期不承诺移动端、手柄专用流程及其他操作系统 | 后续若扩范围，另审输入和画面；不能由所用技术实验推断自动支持 |

以上是首版产品设计要求；兼容性、设备性能与交付完成情况另行验收，本文不宣称已实现。

## UX02 从菜单到结束的实际流程

| 界面／节点 | 玩家可做的事 | 确认后结果与返回边界 |
| --- | --- | --- |
| 主菜单 | 新游戏、继续、规则册、设置、退出 | 有进行中对局时，新游戏须明确确认放弃旧局；取消保留。无存档时继续不可选并说明原因 |
| 路线桌面 | 看当前节点、全图可达路线、公开敌人机制与环境主题；选择下一可达节点 | 先选中查看，再用“进入”确认；确认才锁定分支。不可达节点只读，不可后退刷节点 |
| 法杖袋／编排入口 | 点击后沿长法杖袋打开管理；同屏提供“法杖与词卡”文字按钮 | 非战斗时管理本局词卡、法术和法杖；战斗期间入口标为“查看配置”，打开只读副本 |
| 战斗节点准备 | 显示本场具体站位、属性、生命护甲、攻击计划；进入三步编排与开战检查 | 确认开战才锁定本场输入；此前仍可改配置，不能返回重选已进入的路线节点 |
| 自动战斗 | 暂停、播放、倍速、逐刻、看对象／范围／配置／记录 | 不提供移动、选敌、出牌、调起点或换镶嵌；观察操作不改变战斗结果 |
| 普通胜利 | 看成立刻、剩余生命、本场金币包；整体领取或放弃 | 一次确认结算；没有逐件拆领奖励或再次领取；返回路线 |
| 休整 | 查看恢复量与当前生命，选择恢复、拿词或跳过 | 拿词分支沿现行三候选规则；选择后可拒收但不返还恢复分支，不靠退出换候选 |
| 商店 | 查看固定货架、价格、当前金币、持有数；逐项购买或离开 | 每次交易确认后立即保留；售空／额度满／金币不足说明原因；无刷新、出售或退款 |
| 首领胜利 | 显示本局胜利与最终构筑、路线和战斗摘要 | 按RG基准直接结束本局；不新增未设计的首领奖励商店或局外成长 |
| 失败／认输 | 显示终局原因和最后完整事件，允许查看本场记录 | 结束本局，可返回菜单或开始新局；不能从失败前继续。认输明确确认一次 |
| 设置／规则册 | 音量、字体、速度与信息说明；可从菜单或局内打开 | 战中打开先暂停；关闭后维持暂停，玩家明确播放后继续 |

路线、卡牌库存和正式法术在战外可以反复查看。恢复、领取、购买、进入分支属于会改变本局的决定；打开详情和移动焦点不是一次节点选择。战前编辑只改变配置，不创建新物品。

新局初始提供UX03默认配置及可跳过提示，适用于每一新局；不是首局额外送卡。提示跳过不改变敌人、奖励或起点资源。退出后重开应用，首页以“继续”进入同一存档，不自动开始新局。

## UX03 三步编排、默认配置与开战门槛

| 步骤 | 核心操作 | 必须显示 |
| --- | --- | --- |
| 1 用词卡构句 | 按名词／动词／形容词筛选实际库存，选卡放入句子；连接词由合法关系显示；选择实例或条件绑定 | 每个实际卡片的占用去向、剩余副本；句义角色、完整释义、合法／不合法原因；条件不可凭空增加词义 |
| 2 形成完整法术 | 确认当前句义和挂接关系，保留为本局法术；修改或拆回库存 | 所用实体列表、命中类型、C与L、单／范围结果、支付条件；空白草稿不占卡，放入后按实际实体占用 |
| 3 绑定法杖 | 从已持有杖中选出战位，绑一条法术；调顺序、范围锚点、0–10刻首次冷却起点和两个可换槽 | 杖的固定身份、原范围、借位后目标范围、激活条件；首次释放与正常循环的名义时间轴 |

具体输入：点击选卡再点击位置；拖动等效。Tab／Shift+Tab移动焦点，方向键选择网格或列表项，Enter确认当前操作，Esc返回上一信息层。编排控件提供明确“左移／右移、前置／后置、起点−／＋、拆下”按钮，不能要求记住快捷键。Enter在文字输入中只确认输入，不同时触发开战。

实例绑定只能选准备画面中存在且合法的明确实例；未来可能生成的元素采用合法条件绑定，显示“当前未出现，执行时按条件查找”。不能把不存在的未来对象伪装成已绑定实例。跨战保留句子结构、顺序、锚点、镶嵌和起点；条件原样保留，指向上一场敌人或元素的实例绑定标为失效，须重新绑定或移出出战配置，不自动替换为同格新身份。

**开战门槛UX-C01：允许保存未完成草稿，但开战至少需要1根绑定合法完整法术的出战杖，最多按SG的4根。** 不要求至少一条伤害法术，也不以预测胜率阻止低输出／零输出构筑。其余空杖可留库存；空杖没有镶嵌收益。0根出战不允许开战；合法的零输出构筑仍可开战。

| 开战检查分类 | 例子 | 规则处理 |
| --- | --- | --- |
| 阻止开战的非法配置 | 实体卡重复占用、未完成角色、已失效实例、出战杖绑定空句、超出战上限、未选锚点、起点越界、同物品装两杖 | 指向具体法术／卡／槽；修好或移出出战配置后才能开战 |
| 明示互斥 | 同杖双律环＋攻守转盘 | 不允许装备成该组合；尝试放入时说明冲突并保留原物品，不静默替换 |
| 合法但可能无效 | 当前无匹配元素、预期无可消耗护甲、空心＋自噬长期储层、没有伤害输出、条件将来未必成立 | 黄色文字提示原因，仍允许开战；不把当前无目标误判为句法错误 |
| 名义时间冲突 | 两杖同刻预计开始、后杖覆盖；未来可能被生命伤害取消 | 显示公开仲裁结果及“名义计划，战中可被改期／取消”；不承诺静态预览就是全场预言 |
| 当前无适用事件的镶嵌 | 词义与该镶嵌适配不相交 | 可以保留装备，但明确“本配置当前无适用事件”；不能给空杖被动或免费换成别的效果 |

起始默认配置仅使用SG的12张卡与4根W01，无额外实体。四杖锚点均F3，范围按WG裁切，目标采用合法条件绑定：

| 公开杖位 | 实际完整句 | 首次冷却起点 | 依据PG的首次名义释放 |
| --- | --- | --- | --- |
| 1 | 伤害／敌人 | 0 | 4刻 |
| 2 | 获得／护甲 | 1 | 5刻 |
| 3 | 释放／火焰 | 2 | 7–9刻 |
| 4 | 火焰／伤害／敌人 | 2 | 8刻 |

占用9张卡，剩余获得、护甲、冰霜各1张；可换槽为空。第3杖产生的元素可以供第4杖条件匹配；生成失败时第4杖可能无目标，不能强制补一个元素。后续循环仍可能冲突，例如第15刻两条开始机会按正常规则仲裁；这是可修改的初始配置，不宣称最优或已通过平衡验证。

普通战斗后只清场内临时身份和计数，保留局内物品与配置偏好；涉及上一场实例的引用必须显式处理，不能偷偷重选。用户可以清空默认配置再自行构句；不得把默认句子变成额外不可拆的基础技能。

## UX04 战斗信息与观看操作

| 层级 | 常驻信息 | 展开查看 |
| --- | --- | --- |
| 玩家 | 当前／上限生命、护甲、印记／回响／元素状态（实际存在时）、当前刻、疲劳倒计时 | 状态来源、实际层数、周期量、衰减进度、上一变化原因；玩家没有战场占位 |
| 法杖 | 公开序号、完整法术短名、冷却／释放段／取消状态、下一名义开始、复诵待发与蓄势标志 | 实际词卡、C／L、原范围与目标范围、固定／可换镶嵌、计数及触发条件 |
| 棋盘 | 前后排及格号、占位体、地面、敌人生命护甲、固有属性与当前状态图标＋名称 | 创建来源、宿主资格、形态痕迹、当前对应阈值、是否有有效释放覆盖 |
| 当前变化 | 命中／获得甲／补层／抵消／形态推进等短反馈 | 展开其完整事件和对应一层触发；主动支付与伤害分开标明 |
| 结果记录 | 最近结果及可滚动事件记录 | 按刻、四阶段、完整法术／敌人／环境／状态及来源筛选，失败后仍可查看本场 |

“成功”“被后杖覆盖”“生命受伤取消冷却”“没有合法目标”“材料不足”“合法结果为0”“只消耗旧状态、未生成新状态”使用不同文字与图形，不能都显示成“未生效”。伤害同时显示实际损耗的护甲和生命；疲劳标“生命流失”，不能混同普通伤害。元素转化标“旧身份结束→新元素”，历史焦痕与正在燃烧分栏显示。

选中对象时显示其格子与邻近；选中法杖时显示原范围。借位存在时额外显示目标范围且明确执行者仍选原范围。看后排详情、地面详情有独立可选标签；前排树木不能遮住点击入口，也不能被视觉表现解释为阻挡施法。所有范围检查沿当前规则，点击只是查看。

UX-T01：**1刻＝0.5秒（1×）；观看档位0.5×／1×／2×／4×。** 暂停时提供“前进1刻”。第0刻是进入战斗后的第一逻辑刻；开战／中途恢复先显示暂停的第0刻前初态，点击播放后处理第0刻，随后按所选观看间隔呈现后续刻。恢复不允许改动已锁定配置。

暂停请求在当前完整逻辑刻结清后停下；逐刻执行下一个完整刻，含其四阶段、原事件与获准的一层响应，不能停在支付后收益前来改配置。若刻内已出现胜负则立即沿既定规则终局，不强行补完剩余阶段。屏幕同时显示“已结算到第t刻／下一刻t+1”，避免误读初态与处理后画面。

调整速度不改变刻编号、敌人攻击计划、奖金或疲劳。高速可合并同类表现提示，但完整原因记录保留；暂停／慢速能查看被合并的各次事件。特效不延后规则生效，不用播放动画先后改写阶段顺序。预览只给名义周期与已知条件提示；记录只陈述已经发生的结果，不制造不存在的成功概率。

## UX05 保存、继续与异常反馈

UX-S01：仅1个进行中对局；设置独立保存。节点选择、奖励确认、每次购物、休整选择及领取、战前配置保存、开战锁定、胜负结算分别有明确保存反馈。路线和货架沿固定本局输入保留；候选包一旦确定，保存失败重试不得重新抽取。

| 时点 | 必须保留的玩家结果 | 界面反馈 |
| --- | --- | --- |
| 战前编辑 | 已点击“保存配置”的句子、实体分配与法杖设置 | “配置已保存”；未保存编辑离开时可选择保存或放弃本次编辑，不能误清正式库存 |
| 进入节点／购物／休整／领取 | 已确认选择、金币与物品变化、已生成的固定候选 | “已保存”；未完成保存前不进入下一项不可撤销操作 |
| 确认开战 | 同场配置、敌人、环境初态、固定随机输入及奖励规则 | 显示“本场已锁定”；保存完成后进入暂停初态 |
| 战中退出或异常关闭后继续 | 同场从开头恢复，全部锁定，临时战中进度不作为可重配节点 | “从本场开头继续，配置与战场已锁定”；初态暂停，玩家点击播放 |
| 普通胜利尚未领取 | 胜利本身已成立，奖励为待领取的同一包 | 继续时打开结算页，不重打战斗；领取／放弃只结算一次 |
| 本局结束 | 成立的胜利／失败和可查看的末场摘要 | 进行中对局结束；返回菜单不显示可续打的旧战斗 |
| 保存失败 | 保留当前画面和刚才同一结果，停止继续提交选择 | 显示失败与重试；重试保存同一结果，不刷新商店或奖励，不虚报已保存 |

保存失败时仍可查看信息或退出应用，但离开前提示未保存部分可能丢失；不能承诺故障时已保存实际未落定的内容。已完成并成功保存的节点决定不可回滚。继续功能读取失败时显示原因和重试，禁止静默抹存档或自动替玩家新开局。

认输与放弃旧局需要明确确认，因为它们会结束当前进度；暂停、查看、保存、普通合法购买不叠加无关确认框。错误提示使用玩家语言，不把开发日志放入正常操作路径。

## UX06 时长与理解验收目标

以下是预期范围，不是计时限令；暂停和阅读不消耗游戏刻，不产生时间奖金惩罚。

| 层级 | 验收目标 | 与首版参数的关系 |
| --- | --- | --- |
| 普通战斗，RG常规构筑组A | 中位20–40刻，P90≤60刻 | 1×对应逻辑时长约10–20秒，P90≤30秒 |
| 首领，RG组A | 中位40–70刻，P90≤90刻 | 1×约20–35秒，P90≤45秒 |
| 所有合法构筑的终局上限 | 普通≤80刻、首领≤120刻，必须满足RG疲劳证明前提 | 1×逻辑时长上限40秒／60秒；不是现实墙钟保证 |
| 熟悉规则后的完整局 | 约15–25分钟有效游玩，容许构筑者主动花更久 | 指从开局到终局的战前编辑、看图、购物与正常播放；另记主动暂停和离开应用时间 |
| 首次完整局 | 约20–35分钟，包括可跳过引导 | 不为赶目标强制自动关详情或限时选路 |
| 单次失败解释 | 查看暂停画面／记录后30秒内说清指定结果的直接原因 | 由UX验收任务检验，不能以读过说明替代 |

逻辑时长按“终局刻T×0.5秒”换算刻轴距离，不计第0刻首屏、过场或保存耗时。速度2×时刻轴距离用时减半；奖金始终读T。普通6场都在20–40刻、首领40–70刻的示例合计160–310刻，即80–155秒；这只是区间代入，不是把各场中位数相加得到真实总局分布。极端上限6×80＋120＝600刻＝300秒；读牌和暂停可使现实总时长更长。

有效游玩时间预算目标：首次编排2–4分钟，后续6次战前合计6–12分钟，选路／休整／商店合计3–6分钟，正常战斗播放约1.3–2.6分钟，合计约12.3–24.6分钟。15–25分钟是主要观察目标；上下界不硬卡玩家。首次教学另预算5–10分钟。每局同时记录完整墙钟时长、有效游玩时长、战斗逻辑刻与主动暂停时间，不能只删掉失败或思考较慢样本。

UX-E01：首次教学由四个可跳过提示组成：用实体卡构句→确认完整法术和耗时→绑定法杖并选范围→调冷却起点并指出一次共享槽冲突。玩家使用真实初始库存；不增加无来源卡牌、金币或弱化专属敌人。规则册另有静态例子演示护甲挡伤、生命伤害打断、元素出生／回退、状态抵消与环境痕迹，不创建额外奖励关卡。

## UX07 信息层级、键盘路径与可读性

- 卡面常显词名、词性／适配角色、时间贡献、短规则；详情展开合法输入／结果、支付、范围、触发和正反例。共享的护甲／引爆只有一个实体条目，流派索引可同时收录。
- 以“火／燃烧”“冰／冰冻”“草属性”文字明确区分固有属性和状态；图形轮廓与文字都不同。状态数字显示当前层数，衰减进度放详情，避免把0.5进度误写成仍有半个实体层数。
- 字体100%／125%／150%三档；所有信息面板可滚动、换行，放大后开战／继续／返回和核心生命信息仍可访问。实际布局按UX01显示范围验收。
- 关键对象可点击锁定详情，也可键盘聚焦；悬停不是唯一阅读方式。地图、2×5棋盘和时间轴均提供等价列表入口，不要求精确点中细小模型。
- 提供降低动态效果、关闭闪光／镜头震动、独立降低场景特效和背景装饰的选项；保留落点、状态名称、数值与原因。音量可分别调总音量、音乐、战斗与界面提示；静音保留所有必要信息。
- 所有确认按钮有焦点反馈；关闭面板回到原焦点。危险行为写出“放弃本局”或“认输”，不用仅靠图标表达。
- 背景、前排单位和装饰不覆盖文字面板或后排详情入口；画面浓度可以变，实际2×5与作用范围不变。这里是功能可读性要求，不宣称达到尚未验证的无障碍认证。
